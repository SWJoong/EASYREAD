# 01. 제품 요구사항 (PM)

> 작성 기준: `.claude/skills/pm` 워크플로 · 도메인 근거: `.claude/skills/easyread-domain`

## 1. 제품 개요

**EASYREAD**는 복잡한 한국어 텍스트를 쉬운 정보(Easy-Read)로 바꾸는 작업을 돕는 **MCP 서버**다. 쉬운 정보를 만들어야 하는 사람(공공·복지기관 담당자, 콘텐츠 제작자)이 Claude 같은 LLM 클라이언트에서 이 서버를 연결하면, 검증된 작성 지침·단어 사전·자동 검증 도구를 받아 변환 품질과 속도를 함께 높일 수 있다. 서버는 지침·사전·검증만 제공하고 문장 변환은 클라이언트 LLM이 수행한다 — 그래서 API 키 없이, 오프라인에서, 어떤 MCP 클라이언트에서도 동작한다.

## 2. 문제 정의

- 쉬운 정보 제작은 현재 소수 전문 기관의 수작업에 의존한다. 지침을 아는 사람이 적고, 감수 인력은 더 적어 **생산량이 수요를 따라가지 못한다**.
- 범용 LLM에 "쉽게 써줘"라고만 하면 지침 위반(긴 문장, 이중부정, 어려운 한자어 잔존)과 **사실 왜곡**(날짜·조건 누락)이 섞인 결과가 나오며, 이를 잡아줄 자동 검증 수단이 없다.
- 결과: 공공 안내문·복지 정보가 발달장애인 등 낮은 문해력 독자에게 사실상 전달되지 않는 정보 접근권 공백이 존재한다.

## 3. 대상 사용자

| 구분 | 페르소나 | 필요 |
|---|---|---|
| 직접 사용자 A | **김주무관** — 구청 복지과, 공지문을 쉬운 정보 버전으로도 내야 함. 지침 비전문가 | 지침을 몰라도 따라갈 수 있는 변환·검증 절차 |
| 직접 사용자 B | **박간사** — 발달장애인 지원기관, 쉬운 정보 제작 경험 有 | 초안 작성 시간 단축 + 감수 전 자동 점검 리포트 |
| 직접 사용자 C | **이작가** — 콘텐츠 제작자, 이미 쓴 글의 지침 준수 확인이 필요 | 검증 단독 사용(변환 없이) |
| 최종 수혜자 | 발달장애인, 노인, 아동, 한국어 학습자, 낮은 문해력 독자 | 정확하고 이해 가능한 정보 (제품을 직접 쓰지 않지만 모든 요구사항의 최종 기준) |

## 4. 사용자 시나리오

**S1 — 변환 (김주무관)**: 공지문 원문을 붙여넣고 `simplify-text` 프롬프트 실행 → 클라이언트 LLM이 지침(`get_guidelines`)과 사전(`lookup_easy_word`)을 참조해 초안 생성 → `validate_easy_read`(원문 대조 포함)로 검사 → 위반 항목 수정 후 "감수 전 초안" 고지와 함께 저장.

**S2 — 검증 단독 (이작가)**: 이미 작성한 쉬운 글을 `validate_easy_read`에 입력 → 규칙 ID별 위반 리포트와 대체 제안 확인 → `analyze_readability`로 문서 전체 통계(평균 문장 길이 등) 확인 → 수정.

**S3 — 어휘 탐색 (박간사)**: 작성 중 '수급자격'의 쉬운 표현이 필요 → `lookup_easy_word` 조회 → 대체어와 뜻풀이 문형을 받아 본문에 반영.

## 5. 기능 요구사항

우선순위: MoSCoW. **v0.1(MVP)은 Must만으로 성립한다.**

| ID | 우선순위 | 요구사항 | 수용 기준 (AC) |
|---|---|---|---|
| FR-01 | Must | `validate_easy_read` 도구: 텍스트를 입력받아 [validation-checklist](../../.claude/skills/easyread-domain/references/validation-checklist.md) 규칙 ID 기반 위반 리포트를 반환한다 | SEN-01·SEN-04 위반 예문 입력 시 해당 `ruleId`·`severity`·`span`이 포함된 리포트를 반환하고, 정상 예문에는 해당 위반이 없다 |
| FR-02 | Must | `analyze_readability` 도구: 문장 수, 평균 어절 수, 최장 문장, 어려운 단어 수 등 가독성 통계를 반환한다 | 3문장 표본 입력 시 문서 통계 필드가 모두 채워진 structuredContent를 반환한다 |
| FR-03 | Must | `lookup_easy_word` 도구: 단어를 조회해 쉬운 대체어·뜻풀이를 반환한다 | 사전 등재어 조회 시 대체어 1개 이상 반환, 미등재어는 명시적 `found: false` 응답 |
| FR-04 | Must | `get_guidelines` 도구: 지침을 영역별(문장/어휘/숫자/구성/표기/전체)로 조회한다 | `section: "문장"` 요청 시 SEN 영역 지침 텍스트만 반환한다 |
| FR-05 | Must | `simplify-text` 프롬프트: 지침·사전·검증 절차(guidelines.md §6)를 담아 클라이언트 LLM의 변환을 지시한다 | 생성된 프롬프트에 ① 변환 절차 ② 정확성 원칙(§7) ③ "당사자 감수 전 초안" 고지 지시가 포함된다 |
| FR-06 | Must | 모든 변환 산출 경로에 감수 고지: 도구·프롬프트 어느 경로로든 변환 결과물에는 "감수 전 초안" 문구가 안내된다 (PROC-01) | validate 리포트 말미와 simplify-text 지시문 양쪽에서 고지 확인 |
| FR-07 | Should | `validate_easy_read`에 선택 입력 `original`을 주면 ACC 규칙(날짜·금액·연락처 보존)을 추가 검사한다 | 원문과 날짜가 다른 변환문 입력 시 ACC-01 error 반환 |
| FR-08 | Should | `easy-read-review` 프롬프트: 변환 결과를 지침 관점에서 검토·수정 제안하도록 지시한다 | 프롬프트에 규칙 ID 인용 지시가 포함된다 |
| FR-09 | Should | 리소스 노출: 지침 문서와 사전 데이터를 `easyread://` URI 리소스로 제공한다 | 클라이언트 리소스 목록에 지침·사전이 나타나고 내용 조회가 된다 |
| FR-10 | Could | 검증 설정: 임계값(문장 길이 등)·심각도를 도구 인자로 조정할 수 있다 | `maxWords` 변경 시 SEN-01 판정 경계가 바뀐다 |
| FR-11 | Won't (v0.1) | 형태소 분석 기반 정밀 검사, 원격(HTTP) 서버 모드, 서버 내 LLM API 호출, 문서 파일(hwp/docx) 직접 파싱 | — |

## 6. 비기능 요구사항

## 8. 범위 제외

- 서버가 직접 텍스트를 변환·생성하는 기능 (변환 주체는 클라이언트 LLM — 아키텍처 전제)
- 그림·사진 병기 등 시각 디자인 산출 (안내 문구로만 참고 제공)
- 당사자 감수의 대체 (도구는 감수 전 단계까지만 책임진다)
- 한국어 외 언어
