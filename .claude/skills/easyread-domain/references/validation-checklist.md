# 쉬운 정보 검증 체크리스트 (규칙 ID 체계)

이 문서는 **MCP 서버 `validate_easy_read` 도구의 규칙 엔진 스펙**이자 QA 테스트 케이스의 원본이다. 규칙을 문서·코드·테스트에서 인용할 때 반드시 아래 ID를 쓴다.

각 규칙의 **검사 방식** 열:
- `자동` — 규칙 기반 코드로 판정 가능 (v0.1 규칙 엔진 대상)
- `보조` — 코드로 후보 탐지만 하고 최종 판단은 LLM/사람 (경고로만 보고)
- `수동` — 도구 범위 밖, 감수 단계 항목 (리포트에 안내만)

심각도: `error`(지침 위반 확실) / `warning`(위반 가능성, 확인 필요) / `info`(참고).

## SEN — 문장 규칙

| ID | 규칙 | 검사 방식 | 기본 심각도 | 검사 로직 개요 |
|---|---|---|---|---|
| SEN-01 | 문장이 너무 길다 (기본 임계값: 어절 10개 초과 시 warning, 15개 초과 시 error) | 자동 | warning | 문장 분리 후 공백 기준 어절 수 계산. 임계값은 설정 가능하게 |
| SEN-02 | 복문/이어진 문장 ('-고', '-며', '-지만', '-는데' 등 연결어미로 절 2개 이상 결합) | 보조 | warning | 연결어미 패턴 매칭(오탐 있음 → 보조). 형태소 분석 도입 시 자동 승격 후보 |
| SEN-03 | 피동 표현 ('-되다', '-어지다', '-게 되다', '-당하다') | 보조 | warning | 피동 접미/보조용언 패턴 매칭 |
| SEN-04 | 이중 부정 ('-지 않으면 -할 수 없다' 등 부정 표현 2회 결합) | 자동 | error | 부정 패턴 2개 이상 동시 출현 탐지 |
| SEN-05 | 한 문장에 여러 정보 (병렬 나열 3개 이상 포함) | 보조 | info | 쉼표/나열 조사 빈도 휴리스틱 |

## VOC — 어휘 규칙

| ID | 규칙 | 검사 방식 | 기본 심각도 | 검사 로직 개요 |
|---|---|---|---|---|
| VOC-01 | 어려운 한자어 사용 (사전의 difficult 목록 일치) | 자동 | warning | 단어 사전 매칭 → 대체어 제안 반환 |
| VOC-02 | 불필요한 외래어/외국어 | 자동 | warning | 사전 매칭 + 로마자 연속 탐지 |
| VOC-03 | 전문용어/법령용어에 뜻풀이 없음 | 보조 | warning | 사전의 terminology 목록 매칭 후, 인접 문장에 풀이 패턴('~이란', '~라는 뜻') 존재 여부 확인 |
| VOC-04 | 추상어/관용구/비유 표현 | 보조 | info | 사전의 idiom 목록 매칭 |
| VOC-05 | 풀이 없는 줄임말/약어 첫 사용 | 보조 | warning | 약어 사전 매칭 + 첫 등장 위치에서 괄호 풀이 여부 |
| VOC-06 | 지시어 과다 ('이', '그', '해당' 등 밀도) | 보조 | info | 지시어 빈도/문장 수 비율 |

## NUM — 숫자·날짜 규칙

| ID | 규칙 | 검사 방식 | 기본 심각도 | 검사 로직 개요 |
|---|---|---|---|---|
| NUM-01 | 한글 수사 표기 ('삼십 일' 등) | 자동 | warning | 한글 수사 패턴 탐지 → 아라비아 숫자 제안 |
| NUM-02 | 복잡한 비율/통계 (소수점 백분율 등) | 자동 | info | `\d+\.\d+%` 등 패턴 → "10명 중 N명" 제안 |
| NUM-03 | 상대적 날짜 표현 ('익일', '금주', '차주') | 자동 | warning | 상대 날짜 어휘 목록 매칭 |
| NUM-04 | 읽기 어려운 큰 수 표기 ('1,000,000원') | 자동 | info | 자릿수 콤마 패턴 → 만/억 단위 제안 |

## STR — 구성 규칙

| ID | 규칙 | 검사 방식 | 기본 심각도 | 검사 로직 개요 |
|---|---|---|---|---|
| STR-01 | 행동/결론이 글 앞부분에 없음 | 수동 | info | 구조 판단은 LLM/감수 몫. 리포트에 점검 질문으로 포함 |
| STR-02 | 단락이 너무 길다 (문장 5개 초과) | 자동 | info | 단락별 문장 수 |
| STR-03 | 3개 이상 나열이 문장 안에 있음 (목록화 권장) | 보조 | info | 쉼표 나열 탐지 |
| STR-04 | 절차에 단계 번호 없음 | 수동 | info | 점검 질문으로 포함 |

## TYP — 표기 규칙

| ID | 규칙 | 검사 방식 | 기본 심각도 | 검사 로직 개요 |
|---|---|---|---|---|
| TYP-01 | 풀어 쓰지 않은 기호 (※, ~, &, / 등) | 자동 | warning | 기호 목록 매칭 |
| TYP-02 | 괄호 남용 (문장당 2개 이상) | 자동 | info | 괄호 쌍 개수 |
| TYP-03 | 쌍점/쌍반점 사용 | 자동 | info | 문자 탐지 |

## ACC — 정확성 규칙 (변환 전후 비교)

원문과 변환문을 함께 받았을 때만 검사한다 (`validate_easy_read`의 선택 입력).

| ID | 규칙 | 검사 방식 | 기본 심각도 | 검사 로직 개요 |
|---|---|---|---|---|
| ACC-01 | 날짜/시간 불일치 | 자동 | error | 양쪽에서 날짜 패턴 추출 후 집합 비교 |
| ACC-02 | 금액/수량 불일치 | 자동 | error | 숫자+단위 추출 비교 (단, NUM-02 단순화로 의도된 변경은 원문 값 병기 여부로 판정) |
| ACC-03 | 기관명/고유명사 누락 | 보조 | warning | 원문 고유명사 후보가 변환문에 없으면 경고 |
| ACC-04 | 연락처/URL 불일치 | 자동 | error | 전화번호/URL 패턴 비교 |

## PROC — 프로세스 항목 (도구가 검사하지 않는 것)

리포트 말미에 항상 안내로 포함한다:

- PROC-01: 발달장애 당사자 감수를 거쳤는가 (도구는 감수를 대체하지 않는다)
- PROC-02: 대상 독자에게 실제로 읽혀 이해도를 확인했는가
- PROC-03: 그림/사진 병기 등 시각 자료를 검토했는가

## 리포트 형식 규약

`validate_easy_read`의 결과는 규칙별 위반 목록으로 반환한다. 각 항목: `ruleId`, `severity`, `message`(한국어), `span`(문제 구간 인덱스), `suggestion`(대체 제안, 있을 때만). 요약: 규칙군별 위반 수, 전체 판정(pass / needs-review / fail). 임계값·심각도는 서버 설정으로 조정 가능하게 설계한다.
