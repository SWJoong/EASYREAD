# 쉬운 정보(Easy-Read) 도메인 지식

이 스킬은 EASYREAD 프로젝트의 **단일 도메인 지식 소스**다. 모든 역할(PM/PL/Backend/QA/DevOps)이 계획을 세울 때 여기의 원칙과 규칙 ID를 기준으로 삼는다. 문서마다 규칙을 다르게 해석하면 서버의 검증 로직과 테스트가 어긋나므로, 규칙을 인용할 때는 반드시 아래 규칙 ID(예: `SEN-01`)를 사용한다.

## 쉬운 정보란

복잡한 정보를 발달장애인, 노인, 아동, 한국어 학습자, 낮은 문해력의 사용자가 **스스로 이해할 수 있게** 바꾼 글이다. 단순 요약이 아니라, 정보의 권리 보장 수단이다(발달장애인 권리보장 및 지원에 관한 법률의 의사소통 지원 취지). 따라서 정보를 빼는 것이 아니라 **이해 가능한 형태로 다시 쓰는 것**이 목표다.

## 5대 핵심 원칙 (요약)

1. **한 문장, 한 가지 정보** — 문장을 짧게, 복문 대신 단문으로.
2. **일상어 사용** — 어려운 한자어·외래어·전문용어는 쉬운 말로 바꾸고, 바꿀 수 없으면 바로 뒤에 뜻풀이를 붙인다.
3. **구체적으로** — 추상어, 비유, 관용구, 이중부정을 피한다. 능동태·긍정문으로 쓴다.
4. **중요한 것 먼저** — 결론/행동 지시를 앞에, 배경 설명은 뒤에. 제목과 목록으로 구조화한다.
5. **당사자 검수** — 최종 판단자는 규칙이 아니라 당사자(발달장애인 감수자)다. 도구는 후보를 걸러줄 뿐이다.

## 참조 문서 (필요할 때 읽기)

- **작성 지침 상세** → [references/guidelines.md](references/guidelines.md)
  문장·어휘·숫자·구성·표기 영역별 상세 지침과 변환 예시. PM 요구사항, 변환 프롬프트 설계, 사전 데이터 설계 시 읽는다.
- **검증 체크리스트(규칙 ID 체계)** → [references/validation-checklist.md](references/validation-checklist.md)
  기계 검사 가능성 표시가 붙은 규칙 목록. **MCP 서버 `validate_easy_read` 도구의 규칙 엔진 스펙이자 QA 테스트 케이스의 원본**이다. PL 인터페이스 명세, Backend 구현 계획, QA 계획 작성 시 반드시 읽는다.
