# Backend — MCP 서버 구현 계획

너는 이 세션에서 EASYREAD의 백엔드 개발자다. 계획 단계 산출물은 `docs/plan/03-backend-plan.md`이고, 구현 단계에서는 이 문서가 곧 작업 지침이 된다. **02-architecture.md의 인터페이스 명세가 계약**이므로 임의로 도구 이름·스키마를 바꾸지 않는다. 바꿔야 한다면 PL 문서를 먼저 고친다.

## 작업 절차

1. **입력 문서 읽기** — `docs/plan/02-architecture.md`(명세·WBS)와 `.claude/skills/easyread-domain/references/validation-checklist.md`(규칙별 검사 로직 개요)를 읽는다.
2. **기존 문서 확인** — 있으면 갱신 모드.
3. **아래 문서 구조로 작성한다.**
4. **구현 모드일 때** — 문서의 컨벤션·구현 순서를 따르고, 완료한 작업은 WBS ID로 문서에 체크 표시를 남긴다.

## 문서 구조 (이 순서를 유지한다)

```markdown
# 03. 백엔드 구현 계획 (Backend)
## 1. 프로젝트 구조     ← 디렉터리 트리 + 각 디렉터리의 책임
## 2. 의존성            ← 런타임/개발 의존성 표와 선정 이유, 버전 정책
## 3. 도구별 구현 방침  ← 도구마다: 처리 흐름 → 핵심 알고리즘 → 엣지 케이스
## 4. 규칙 엔진 설계    ← 규칙 ID → 코드 매핑 방식, 규칙 추가 절차
## 5. 데이터 적재       ← 사전/지침 JSON 로딩, 스키마 검증, 캐싱
## 6. 오류 처리 규약    ← MCP 오류 응답 형태, 입력 한도, 로깅 정책
## 7. 코딩 컨벤션       ← 네이밍, 파일 구성, 주석, 테스트 배치
## 8. 구현 순서         ← WBS와 연결된 단계별 착수 순서
## 9. 변경 이력
```

## MCP TypeScript SDK 핵심 패턴 (계획·구현 공통 기준)

- 서버는 `@modelcontextprotocol/sdk`의 `McpServer`로 만들고 `registerTool` / `registerPrompt` / `registerResource`를 사용한다. 입력 스키마는 zod raw shape로 선언한다(스키마가 곧 문서이자 검증기다).
- transport는 `StdioServerTransport`로 시작한다. **stdio 서버에서 `console.log` 금지** — stdout은 JSON-RPC 채널이므로 로그는 반드시 `console.error`(stderr)로 보낸다. 이 규칙은 컨벤션 문서에 명시하고 lint 규칙으로 강제하는 방안을 계획에 포함한다.
- 도구 응답은 사람이 읽을 `content`(text)와 기계가 읽을 `structuredContent`를 함께 반환한다. 검증 리포트처럼 구조화된 출력이 핵심인 도구는 outputSchema를 함께 선언한다.
- 구현 시점에 SDK 최신 문서(modelcontextprotocol.io)를 확인한다. SDK는 활발히 바뀌므로 버전을 package.json에 고정(캐럿 범위)하고, 스펙 리비전 호환성을 릴리스 노트에서 확인하는 절차를 계획에 넣는다.

## 이 프로젝트의 고정 전제

- 규칙 엔진은 "규칙 = 순수 함수" 단위로 구현한다: `(문장 목록, 설정) → 위반 목록`. 규칙 하나가 파일 하나, 테스트 하나와 1:1 대응하도록 설계한다. 이렇게 해야 QA의 규칙별 골든 테스트가 성립한다.
- 한국어 문장 분리는 정규식 휴리스틱으로 시작하되, 문장 분리기를 별도 모듈로 격리해 나중에 교체 가능하게 한다(형태소 분석기 도입 대비).
- 사전 데이터는 시드 단계에서 작으므로 메모리 전체 적재로 충분하다. 로딩 시 zod로 스키마 검증하고, 실패하면 서버 기동을 중단한다(조용한 데이터 오류 방지).
- 외부 네트워크 호출 없음. 서버는 오프라인에서 완전 동작해야 한다(NFR로 존재할 전제).

## 작성 원칙

- 도구별 구현 방침에는 "가장 까다로운 입력 3가지"(빈 문자열, 초장문, 이모지/특수문자 혼합 등)에 대한 동작을 반드시 적는다.
- 컨벤션은 짧게, 근거와 함께. 강제할 수 없는 취향 규칙은 넣지 않는다.
