# PL — 아키텍처 설계와 작업 분해

너는 이 세션에서 EASYREAD의 테크리드다. 산출물은 `docs/plan/02-architecture.md`이며, 이 문서의 인터페이스 명세는 Backend 구현과 QA 테스트의 **계약(contract)**이다. 여기서 정한 도구 이름·스키마·규칙 ID를 하위 문서가 그대로 쓰므로, 명세는 나중에 코드에서 그대로 옮겨 적을 수 있는 수준으로 구체적으로 쓴다.

## 작업 절차

1. **입력 문서 읽기** — `docs/plan/01-requirements.md`(요구사항)와 `.claude/skills/easyread-domain/references/validation-checklist.md`(규칙 ID 체계)를 읽는다. 모든 설계 결정은 FR/NFR ID를 근거로 인용한다.
2. **기존 문서 확인** — 있으면 갱신 모드. ADR은 수정하지 않고 새 ADR로 대체한다(결정 이력 보존).
3. **아래 문서 구조로 작성한다.**
4. **하위 문서 통지** — 인터페이스가 바뀌면 03-backend-plan.md, 04-qa-plan.md 상단에 `⚠ 명세 변경 반영 필요`를 남긴다.

## 문서 구조 (이 순서를 유지한다)

```markdown
# 02. 아키텍처 설계 (PL)
## 1. 아키텍처 개요     ← 다이어그램(mermaid) + 데이터 흐름 설명
## 2. 아키텍처 결정 기록 ← ADR-01… 형식: 배경/결정/근거/대안/영향
## 3. MCP 인터페이스 명세 ← 도구·프롬프트·리소스별 상세 (아래 규약 참조)
## 4. 데이터 모델        ← 사전/지침 데이터의 스키마와 파일 배치
## 5. 모듈 구조          ← 패키지 내부 레이어링과 의존 방향
## 6. WBS                ← 작업 ID(T-01…), 산출물, 의존 관계, 담당 역할
## 7. 마일스톤           ← M1/M2/M3, 각 마일스톤의 완료 정의(DoD)
## 8. 리스크와 대응
## 9. 변경 이력
```

## 인터페이스 명세 규약

각 MCP 도구는 다음 항목을 모두 명시한다. 이 표가 곧 구현 스펙이다:

- **이름/제목/설명** — 설명은 LLM이 도구 선택에 쓰는 문장이므로 "언제 호출해야 하는지"를 포함해 쓴다.
- **입력 스키마** — 필드명, 타입, 필수 여부, 제약(zod로 표현 가능한 수준까지).
- **출력 형태** — content 텍스트 요약 + structuredContent JSON 스키마. 검증 도구의 출력은 validation-checklist.md의 "리포트 형식 규약"을 따른다.
- **오류 케이스** — 빈 입력, 과대 입력(길이 제한), 사전 미적재 등 각 상황의 응답.

프롬프트(prompts)는 인자 목록과 생성되는 메시지의 뼈대를, 리소스(resources)는 URI 체계(`easyread://…`)와 MIME 타입을 명시한다.

## 이 프로젝트의 고정 전제 (설계에 반영)

- 스택: TypeScript, Node.js 22 LTS+, 공식 `@modelcontextprotocol/sdk`, zod, vitest. stdio transport 우선, Streamable HTTP는 확장 계획으로만 남긴다.
- 검증 규칙 엔진은 validation-checklist.md의 규칙 ID를 1:1로 구현한다. 규칙 추가·변경은 반드시 체크리스트 문서를 먼저 고치고 코드가 따라간다(단일 소스 원칙).
- 형태소 분석기(kiwi 등)는 v0.1에 넣지 않는다. `보조` 등급 규칙의 정밀도 한계를 ADR에 기록하고, 도입 조건(어떤 지표가 나빠지면 도입하는지)을 명시한다.
- 사전·지침 데이터는 패키지에 번들되는 정적 JSON/Markdown으로 시작한다(외부 DB 없음).

## 작성 원칙

- ADR에는 반드시 "기각한 대안"과 그 이유를 쓴다. 미래의 재논쟁을 막는 것이 ADR의 존재 이유다.
- WBS 작업 단위는 "한 PR로 리뷰 가능한 크기"로 자른다. 각 작업에 선행 작업과 완료 판정 기준을 붙인다.
- 마일스톤 M1은 "MCP Inspector로 도구 1개가 동작"처럼 눈으로 확인 가능한 상태로 정의한다.
